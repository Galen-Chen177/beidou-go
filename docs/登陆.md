# 冒险岛 GMS v83 登录流程抓包分析

## 协议概述

- **版本**: GMS v83 (MapleStory Global)
- **加密方式**: 
  - 首个包(Hello)为明文，无包头
  - 后续所有包：**4字节包头 + AES-OFB加密 + 自定义Shanda加密**
- **包结构** (Hello之后):
  - Byte 0-3: 4字节包头，包含加密后的包长度（与IV异或）
  - Byte 4+: 加密数据体
    - 解密后：2字节 Opcode (小端序) + 载荷
- **Opcode 定义文件**: 
  - 客户端→服务端: [RecvOpcode.java](gms-server/src/main/java/org/gms/net/opcodes/RecvOpcode.java)
  - 服务端→客户端: [SendOpcode.java](gms-server/src/main/java/org/gms/net/opcodes/SendOpcode.java)
- **关键代码文件**:
  - 协议编解码: [GMSV83PacketProtocol.java](gms-server/src/main/java/org/gms/net/encryption/protocol/GMSV83PacketProtocol.java)
  - AES加密: [MapleAESOFB.java](gms-server/src/main/java/org/gms/net/encryption/MapleAESOFB.java)
  - 自定义加密: [MapleCustomEncryption.java](gms-server/src/main/java/org/gms/net/encryption/MapleCustomEncryption.java)
  - 封包构造: [PacketCreator.java](gms-server/src/main/java/org/gms/util/PacketCreator.java)

## 抓包数据详细分析

### 包1: Server → Client — Server Hello (握手包，明文)
```
0000   0e 00 53 00 01 00 31 46 72 7a e9 52 30 78 25 08
```
**大小**: 16 字节 (明文，无包头，无加密)

**结构解析** (对应 `PacketCreator.getHello()`):
| 偏移 | 字节 | 字段 | 值 | 说明 |
|------|------|------|-----|------|
| 0-1 | `0E 00` | short(0x0E) | 0x000E | Hello包标识 |
| 2-3 | `53 00` | short(version) | 83 | MapleStory 客户端版本号 (小端序) |
| 4-5 | `01 00` | short(1) | 1 | 固定标志位 |
| 6 | `31` | byte(49) | 49 | 固定常量 (ASCII '1') |
| 7-10 | `46 72 7a e9` | recvIv[4] | 70,114,122,233 | 服务端接收IV (用于解密客户端发来的数据) |
| 11-14 | `52 30 78 25` | sendIv[4] | 82,48,120,37 | 服务端发送IV (用于加密发往客户端的数据) |
| 15 | `08` | byte(8) | 8 | 地区/语言标识 (8 = 东南亚/其他) |

**IV生成逻辑** ([InitializationVector.java](gms-server/src/main/java/org/gms/net/encryption/InitializationVector.java)):
- `recvIv = {70, 114, 122, random}` → 前三个字节固定 (`F`, `r`, `z`)，最后一位随机
- `sendIv = {82, 48, 120, random}` → 前三个字节固定 (`R`, `0`, `x`)，最后一位随机

**握手后**：客户端和服务端分别用对应的IV初始化 AES-OFB 密码器，后续所有通信均加密。

### 包2: Client → Server — Client Hello / 握手确认
```
0000   29 e9 2b e9 c2 94
```
**大小**: 6 字节 (4字节包头 + 2字节加密数据)

这是客户端在收到Hello并建立加密通道后，发送的第一个加密包。2字节的数据体仅包含一个Opcode（无载荷），可能是 `PONG (0x18)` 或握手确认包，用于验证加密通道已就绪。

**包头结构** (对应 `MapleAESOFB.getPacketHeader()`):
| 偏移 | 字节 | 说明 |
|------|------|------|
| 0-3 | `29 e9 2b e9` | 4字节包头 = 加密后的包长度 |
| 4-5 | `c2 94` | 加密后的数据 (2字节，解密后为Opcode) |

**包头解密公式** (`MapleAESOFB.decodePacketLength()`):
```
iiv = (iv[2] << 8 | iv[3]) ^ mapleVersion
packetLength = ((iiv >>> 8) ^ header[2]) << 8 | ((iiv & 0xFF) ^ header[3])
// 或简化: ((header[1] ^ header[3]) << 8) | (header[0] ^ header[2])  然后字节交换
```

### 包3: Client → Server — 账号密码登录
```
0000   cf 2e e0 2e 3b a1 f5 9a 99 d3 98 c7 c1 d8 53 e7
0010   f1 11 b1 52 75 12 a9 88 ed 2a d6 90 04 07 f5 6f
0020   4b 22 4c 99 0e 1b ad c8 f7 c0 5e 8d 32 94 02 3e
0030   1c 72 a3
```
**大小**: 51 字节 (4字节包头 + 47字节加密数据)
**Opcode**: `0x01` (`LOGIN_PASSWORD`)

**对应Handler**: [LoginPasswordHandler.java](gms-server/src/main/java/org/gms/net/server/handlers/login/LoginPasswordHandler.java)

**解密后数据结构**:
```
Opcode:     short(0x01)          — LOGIN_PASSWORD
login:      string               — 账号名(小端序长度前缀 + 字节)
pwd:        string               — 密码(小端序长度前缀 + 字节)
skip:       byte[6]              — 客户端本地掩盖的6个0x00
hwid:       byte[4]              — 硬件ID (HWID)
```

**处理流程**:
1. 读取 `login` 和 `pwd` 字符串
2. skip 6字节
3. 读取4字节HWID
4. 调用 `c.login(login, pwd, hwid)` 验证密码 (可能是BCrypt或SHA512)
5. 检查封禁状态 (IP封禁 / MAC封禁 / 临时封禁 / 永久封禁)
6. 成功则调用 `finishLogin()` 更新登录状态为 `LOGIN_LOGGEDIN`
7. 发送认证成功包

---

### 包4: Server → Client — 登录认证成功
```
0000   d4 da e5 da 9f 87 f3 f8 e1 1c ea 87 12 b7 e8 5e
0010   14 a4 8a 68 32 86 bc 43 fa 84 d7 d9 94 1c af 8e
0020   b9 91 ae 63 48 b3 08 4a 55 9e ab 8a ab cb 55 39
0030   1a 65 b8 aa b4
```
**大小**: 53 字节 (4字节包头 + 49字节加密数据)
**Opcode**: `0x00` (`LOGIN_STATUS`)

**对应方法**: `PacketCreator.getAuthSuccess()`

**解密后数据结构**:
```
Opcode:      short(0x00)          — LOGIN_STATUS
accountId:   int(0)               — 保留位，写死0
             short(0)             — 保留位，写死0
accID:       int                  — 账号数据库ID
gender:      byte                 — 性别 (0=男, 1=女)
isGM:        bool                 — 是否GM账号
adminByte:   byte                 — 管理员标识 (GM=0x80, 普通=0x00)
country:     byte                 — 国家代码 (0)
accountName: string               — 账号名
             byte(0)              — 结束符
quietBan:    byte                 — 静默封禁标志 (0=否)
             long(0)              — 静默封禁时间戳
             long                 — 账号创建时间戳
             int(1)               — 1=移除"选择你想进入的世界"提示
pinEnabled:  byte                 — PIN码状态: 0=需要设置PIN, 1=PIN已禁用
picEnabled:  byte                 — PIC状态: 0=需要注册PIC, 1=需要输入PIC, 2=PIC已禁用
```

**登录失败时的错误码** (`PacketCreator.getLoginFailed()`):
| 错误码 | 含义 |
|--------|------|
| 2 | 账号已封禁 |
| 3 | ID已删除或屏蔽 |
| 4 | 密码错误 |
| 5 | 未注册的ID (如开启auto_register则自动注册) |
| 6 | 系统错误 |
| 7 | 已在其他地方登录 |
| 10 | 服务器连接数过多 |
| 11 | 仅限20岁以上用户 |

### 包5: Client → Server — 请求服务器列表
```
0000   c2 e3 c0 e3 fe e0
```
**大小**: 6 字节 (4字节包头 + 2字节加密数据)
**Opcode**: `0x0B` (`SERVERLIST_REQUEST`)

**对应Handler**: [ServerlistRequestHandler.java](gms-server/src/main/java/org/gms/net/server/handlers/login/ServerlistRequestHandler.java)

**解密后数据结构**: 仅 Opcode，无载荷。

**处理流程**:
1. 获取所有世界(World)列表
2. 遍历每个世界，发送 `SERVERLIST` 包(包6)
3. 发送服务器列表结束标记(包7)
4. 发送上次连接的世界(包8)
5. 发送推荐世界(包9)

> **注意**: 如果服务端开启了PIN/PIC功能，在认证成功后客户端会先发送 `AFTER_LOGIN (0x09)` 进行PIN/PIC验证，然后才发 `SERVERLIST_REQUEST`。本例中PIN/PIC均被禁用，所以客户端直接请求服务器列表。

### 包7: Server → Client — 服务器列表结束标记
```
0000   99 a2 9a a2 b1 18 6f
```
**大小**: 7 字节 (4字节包头 + 3字节加密数据)
**Opcode**: `0x0A` (`SERVERLIST`)

**对应方法**: `PacketCreator.getEndOfServerList()`

**解密后数据结构**:
```
Opcode:  short(0x0A)    — SERVERLIST (与服务器列表使用同一Opcode)
endMark: byte(0xFF)     — 0xFF 表示服务器列表结束
```

客户端收到 `byte == 0xFF` 的 `SERVERLIST` 包后，知道服务器列表已全部发送完毕。

---

### 包8: Server → Client — 上次连接的世界
```
0000   d7 c8 d1 c8 95 1b 90 90 cb 12
```
**大小**: 10 字节 (4字节包头 + 6字节加密数据)
**Opcode**: `0x1A` (`LAST_CONNECTED_WORLD`)

**对应方法**: `PacketCreator.selectWorld()`

**解密后数据结构**:
```
Opcode:   short(0x1A)    — LAST_CONNECTED_WORLD
worldId:  int            — 推荐选择的世界ID (0 = 第一个世界)
```

此包告知客户端上次登录的是哪个世界，客户端会在世界选择界面高亮该世界。

---

### 包9: Server → Client — 推荐世界消息
```
0000   9f ac 84 ac 7c 61 b3 36 aa 33 77 fe e7 2b d0 f4
0010   1a c7 c7 90 a0 19 38 e1 15 02 89 d2 d5 df fd
```
**大小**: 46 字节 (4字节包头 + 42字节加密数据)
**Opcode**: `0x1B` (`RECOMMENDED_WORLD_MESSAGE`)

**对应方法**: `PacketCreator.sendRecommended()`

**解密后数据结构**:
```
Opcode:   short(0x1B)    — RECOMMENDED_WORLD_MESSAGE
count:    byte           — 推荐世界数量
// 每个推荐世界:
  worldId:  int          — 世界ID
  message:  string       — 推荐消息文本
```

此包在世界选择界面显示推荐消息（如 "New!"、"Hot!" 等标签）。

## 后续流程 (抓包未包含，来自代码分析)

### 步骤 A: Client → Server — 请求角色列表
**Opcode**: `0x05` (`CHARLIST_REQUEST`)
**Handler**: [CharlistRequestHandler.java](gms-server/src/main/java/org/gms/net/server/handlers/login/CharlistRequestHandler.java)

```
Opcode:   short(0x05)
          byte             —  (跳过一个字节)
world:    byte             — 世界ID
channel:  byte             — 频道序号 (实际频道 = channel + 1)
```

### 步骤 B: Server → Client — 角色列表
**Opcode**: `0x0B` (`CHARLIST`)
**方法**: `PacketCreator.getCharList()`

```
Opcode:      short(0x0B)    — CHARLIST
status:      byte           — 状态 (0=成功)
charCount:   byte           — 角色数量
// 每个角色:
  addCharEntry(...)         — 角色详细信息 (外观、等级、职业、装备等)
picEnabled:  byte           — PIC状态
charSlots:   int            — 可用角色槽位数量
```

### 步骤 C: Client → Server — 选择角色
**Opcode**: `0x13` (`CHAR_SELECT`)
**Handler**: [CharSelectedHandler.java](gms-server/src/main/java/org/gms/net/server/handlers/login/CharSelectedHandler.java)

```
Opcode:       short(0x13)
charId:       int             — 角色ID
macs:         string          — MAC地址信息
hostString:   string          — 主机标识字符串 (含HWID)
```

### 步骤 D: Server → Client — 频道服务器IP地址
**Opcode**: `0x0C` (`SERVER_IP`)
**方法**: `PacketCreator.getServerIP()`

```
Opcode:     short(0x0C)
            short(0)          — 保留
ipAddr:     byte[4]           — 频道服务器IPv4地址
port:       short             — 频道服务器端口
charId:     int               — 角色ID
            byte[5] (0x00)    — 保留
```

客户端收到此包后，断开登录服务器连接，使用给出的IP和端口连接到频道服务器(游戏服务器)，开始实际游戏。

## 加密流程补充说明

### AES-OFB 加密 ([MapleAESOFB.java](gms-server/src/main/java/org/gms/net/encryption/MapleAESOFB.java))
- 使用固定的 AES 密钥
- IV 由 Hello 包交换，每次连接随机生成
- 加密后 IV 会自动更新 (`getNewIv()`)

### 自定义 Shanda 加密 ([MapleCustomEncryption.java](gms-server/src/main/java/org/gms/net/encryption/MapleCustomEncryption.java))
- AES解密/加密前后各应用一层自定义混淆
- 6轮变换，奇偶轮方向和处理不同
- 包含位移(rollLeft/rollRight)、取反、异或、加减等操作

### 包头发送流程
1. 组装 Opcode + 载荷
2. 应用 Shanda `encryptData()` 
3. 应用 AES-OFB `sendCypher.crypt()`
4. 计算并前置4字节包头 `getEncodedHeader(length)`

### 包头接收流程
1. 读取4字节包头
2. 验证包头 `isValidHeader()` (检查是否与版本号+IV匹配)
3. 从包头计算数据长度 `decodePacketLength()`
4. 读取加密数据
5. AES-OFB `receiveCypher.crypt()` 解密
6. Shanda `decryptData()` 解密
7. 读取 Opcode，分发到对应 Handler
