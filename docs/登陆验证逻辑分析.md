## 1. 数据包路由（如何到达处理器）

在 [PacketProcessor.java:149](../gms-server/src/main/java/org/gms/net/PacketProcessor.java#L149)：

```java
registerHandler(RecvOpcode.LOGIN_PASSWORD, new LoginPasswordHandler());
```

## 2. 客户端数据解析（`LoginPasswordHandler.handlePacket` — 第48行）

客户端发来的原始字节流被包装为 `InPacket`（实现类 `ByteBufInPacket`，基于 Netty 的 `ByteBuf`），解析过程如下：

```java
// 第55行: 读取登录名（字符串）
String login = p.readString();  // 先读2字节长度(short LE)，再读N字节UTF-8

// 第56行: 读取密码明文（字符串）
String pwd = p.readString();    // 同上

// 第59行: 跳过6字节（这段是客户端本地掩码填充的零值，无意义）
p.skip(6);

// 第61行: 读取4字节硬件ID
byte[] hwidNibbles = p.readBytes(4);
Hwid hwid = new Hwid(HexTool.toCompactHexString(hwidNibbles));
```

### 客户端数据包格式（登陆包 `0x01`）

```
| 字段        | 类型       | 长度       | 说明          |
|------------|------------|------------|--------------|
| login      | string     | 2+N 字节    | 账号名（2字节长度前缀 + UTF-8内容）|
| password   | string     | 2+N 字节    | 密码明文（同上） |
| padding    | bytes      | 6 字节      | 客户端掩码，全是0 |
| hwid       | bytes      | 4 字节      | 硬件ID指纹    |
```

### `readString()` 的实现

位于 [ByteBufInPacket.java:52-57](../gms-server/src/main/java/org/gms/net/packet/ByteBufInPacket.java#L52-L57)：

```java
public String readString() {
    short length = readShort();           // 小端序读取2字节→字符串长度
    byte[] stringBytes = new byte[length];
    byteBuf.readBytes(stringBytes);       // 读取N字节原始数据
    return new String(stringBytes, CharsetConstants.getCharset(...));  // 按客户端语言编码转String
}
```

## 3. 密码校验逻辑（`Client.login` — 第653行）

`LoginPasswordHandler` 调用 `c.login(login, pwd, hwid)` 进入 [Client.java:653-731](../gms-server/src/main/java/org/gms/client/Client.java#L653-L731)：

### 校验流程

1. **防爆破**：尝试次数超过4次，直接关闭连接返回`6`
2. **查库**：
   ```sql
   SELECT id, password, gender, banned, pin, pic, characterslots, tos, language
   FROM accounts
   WHERE name = ?
   ```
3. **多级密码校验**：
   - 如果 `password` 字段以 `$2` 开头（bcrypt hash 标志）→ 用 `BCrypt.checkpw()` 验证
   - 否则按**明文**、**SHA-1**、**SHA-512** 依次匹配（兼容老数据）
   - bcrypt 迁移模式：如果匹配的是旧 hash，自动升级为 bcrypt 并回写数据库
4. **同协议条款检测**：`tos` 字段为 0 表示未同意协议条款
5. **多开检测**：调用 `SessionCoordinator.attemptLoginSession()` 检查同账号/同 HWID 是否已在线

### 返回值含义

| loginok | 含义 |
|---------|------|
| 0 | 登陆成功 |
| 3 | 账号被封禁 |
| 4 | 密码错误 |
| 5 | 账号不存在（触发自动注册） |
| 6 | 尝试次数过多 |
| 7 | 已在其他位置登录 |
| 10 | 远端处理中 |
| 13 | 远端达到连接上限 |
| 16 | 多账号尝试限制 |
| 17 | 远端已登录 |
| 23 | 未同意服务条款 |
| -10 | 需要迁移到 bcrypt（旧 hash 匹配） |
| -23 | 需要同意 TOS 并迁移到 bcrypt |

## 4. 完整流程图

```
客户端 → [TCP] → Netty网络层
                  ↓
           PacketProcessor (根据opcode=0x01路由)
                  ↓
          LoginPasswordHandler.handlePacket()
                  ↓
          InPacket.readString() → login (账号)
          InPacket.readString() → pwd  (密码明文)
          InPacket.skip(6)      → 跳过填充
          InPacket.readBytes(4) → hwid (硬件ID)
                  ↓
          Client.login(login, pwd, hwid)
                  ↓
          SQL查询 accounts 表
                  ↓
          BCrypt.checkpw() / SHA1 / SHA512 验证密码
                  ↓
          SessionCoordinator 多开检测
                  ↓
          成功 → PacketCreator.getAuthSuccess(c)
          失败 → PacketCreator.getLoginFailed(errorCode)
```

---

## 关键点总结

- **密码是明文传输的**（客户端没有做hash），服务器端存储的是 bcrypt/SHA hash
- 密码校验支持 **bcrypt、SHA-1、SHA-512** 三种格式，兼容历史数据，并支持自动迁移到 bcrypt
- 数据解析通过 Netty `ByteBuf` 实现，数值全部用**小端序（LE）**读取，字符串用**2字节长度前缀 + UTF-8内容**的格式
- 还有一套独立的 Web 后台认证走 `AuthService`（JWT），用于管理后台接口
- 自动注册功能（`automatic_register` 配置项）：当账号不存在时，自动用客户端提交的密码创建账号
